# users/me: GET and PATCH (task 3.6)

- Status: completed

## Objective

`users.me.get` (GET /v1/me) and `users.me.patch` (PATCH /v1/me) are mounted, contract-green, and tested. GET returns the fresh `MeDto` envelope; PATCH partially updates the profile with the family's exact semantics: omitted fields unchanged, `null` clears, strings trimmed and stored, at least one profile field required, strings 1–100 chars, unknown body fields rejected, `Idempotency-Key` supported (`scopeKey: "users.me.patch"`), and the response is the re-read `MeDto` (not a patch echo).

## Behavior reference (backend-core-kit recon)

- GET: guard → fresh MeDto from the row; missing or `DELETED` user → 401 `UNAUTHORIZED` (missing subject = unusable principal). Codes: `UNAUTHORIZED`, `INTERNAL`.
- PATCH body: `{ profile: PatchMeProfileDto }` with `profile` required; `PatchMeProfileDto` fields `displayName`/`givenName`/`familyName` all optional nullable strings, trimmed before storage, min length 1 after trim, max length 100; `{}` or `null` profile, whitespace-only values, and unknown fields → 400 `VALIDATION_FAILED` (empty-profile issue attaches to `profile`; whitespace attaches to `profile.<name>`). Profile image is output-only and not patchable here.
- PATCH flow: guard → idempotency (optional header) → build the column set from defined keys only → single `users` row update (profile fields + `updatedAt`) → re-read → MeDto; `DELETED`/missing → 401 `UNAUTHORIZED`. Codes: `VALIDATION_FAILED`, `UNAUTHORIZED`, `IDEMPOTENCY_IN_PROGRESS`, `CONFLICT`, `INTERNAL`.

## Constraints

- The users feature owns the `/v1/me*` routes; it consumes the auth feature's public surface only (`../auth/index`), never internals.
- Request DTOs for this surface use strict objects (unknown fields rejected — the family's `forbidNonWhitelisted` policy); the existing auth request DTOs are tightened the same way with a test, since body-level unknown-field rejection was previously only enforced for query params.
- `MeDto` keeps its existing shared contract schema; `MeEnvelopeDto` (`{ data: MeDto }`) lands now with the snapshot's id and required list.
- DELETED handling lives in the projection: `loadMe` returns `undefined` for missing or `DELETED` users so routes map it to 401 `UNAUTHORIZED`; the OIDC exchange path keeps treating `undefined` as an internal inconsistency (it only loads just-verified users).
- Manifest moves `users.me.get` and `users.me.patch` to `implemented`; the emitter gains the `Users` tag; parity + Spectral must stay green.

## Impact Areas

- API / contract: two operations mounted (implemented surface grows to 11 operations); Auth/users: the first users routes; Budget: PATCH writes one users row per call (idempotent replays write none).

## Acceptance Criteria

1. GET returns the fresh Me projection with the envelope and the dialect headers; 401 without/with an invalid token; 401 for `DELETED` users.
2. PATCH semantics tested: sets trimmed values, clears with `null`, leaves omitted fields unchanged, rejects `{}` profile (field `profile`), whitespace-only (field `profile.displayName`), over-length strings, unknown fields, and unknown top-level keys; idempotent replay returns the identical body with `Idempotency-Replayed: true`; key reuse with a different payload → 409 `CONFLICT`.
3. Emitted spec carries both operations with the snapshot's exact shapes (resolved comparison) and the `Users` tag; manifest + parity + Spectral green; `npm run verify:ci` green.

## Completion Notes

`users.me.get` and `users.me.patch` are mounted, contract-green, and tested, with the users
routes owning `/v1/me*` and consuming only exported feature surfaces. The strictness approach
was refined during implementation: `z.strictObject` would emit `additionalProperties: false`
and drift parity, and zod strips unknown keys before handlers see them, so unknown-field
rejection is a `rejectUnknownKeys` check over the **raw JSON captured by a platform middleware**
(`captureRawJson`, applied to the write routes; the four auth bodies gained the same check).
PATCH trims strings and rejects whitespace-only values with `profile.<field>` issues, clears on
`null`, leaves omitted fields unchanged, maps missing/`DELETED` users to 401 `UNAUTHORIZED`
(`loadMe` now treats `DELETED` as missing), and runs the platform idempotency middleware
method-scoped to PATCH — mounting it on the shared `/v1/me` path unconditionally made GETs 500
("only supported for write endpoints"), which the tests caught. The emitter gained the `Users`
tag; the manifest now lists 11 implemented operations.
