# R2 module: presigned PUT/GET helpers (task 4.3)

- Status: completed
- Owner: fikrilal
- Risk: medium
- Date: 2026-10-11
- Related ADRs / proposals: ADR-0007 (R2 owns objects; the Worker never proxies payloads), ADR-0005 (budget); roadmap task 4.3

## Objective

The R2 module lands: a typed `ObjectPresigner` port that produces SigV4 presigned PUT/GET URLs
against the R2 S3 endpoint, configuration for the account/bucket/credentials, credential
redaction, a budget rule that confines the signing dependency to the platform, and tests. Per
the roadmap the module lands ahead of its first consumer (users/me profile images, a later
task); it is exercised by its own specs, and a credentialed R2 smoke stays a follow-up.

## Approach (verified against the live docs, page updated 2026-08-22)

- R2 presigning is pure SigV4 over the S3 API with **no communication with R2**: endpoint
  `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`, region `auto`, service `s3`, expiry 1s..7
  days (604800), path-style object URLs (the AWS CLI/boto3 style). No Worker R2 binding is
  involved — the Worker never touches objects (ADR-0007), so there is nothing to confine
  except the credentials.
- Signing is delegated to `aws4fetch` (Cloudflare's recommended tiny signer; ~5 KB, added as a
  runtime dependency) instead of hand-rolled canonicalization. The dependency is verified
  against AWS's documented SigV4 example vector inside the test suite — the pinned library
  reproduces the documented signature `aeeed9bb…d404` for the classic `examplebucket` example
  — and our wrapper's assembly (host, path encoding, datetime format, parameters) is frozen by
  golden-URL tests.
- Credentials: `R2_ACCOUNT_ID` and `R2_BUCKET` are non-secret vars (placeholders until a real
  account is wired, like the D1 ids); `R2_ACCESS_KEY_ID`/`R2_SECRET_ACCESS_KEY` are secrets
  (`wrangler secret`, `.dev.vars` locally). The secret joins `SENSITIVE_KEYS` redaction.
- The port throws `VALIDATION_FAILED` for caller errors (empty/oversized key, expiry outside
  1..604800) and the request accessor throws `INTERNAL` ("R2 is not configured") when the
  credentials are absent, mirroring `databaseFrom`/`configFrom`.

## Constraints

- Default expiry 300s; hard cap 604800s (platform maximum); integer-only expiries.
- Object keys are normalized (trim, strip leading slashes) and encoded per path segment, so
  slashes stay structural and spaces/unicode are safe.
- `aws4fetch` imports are confined to `src/platform/storage/` by a budget rule; features use
  the port.
- Tests must be deterministic: the signer takes the injected `Clock`, so the datetime is fixed
  in specs; no network calls anywhere in the suite.

## Impact Areas

- Platform: new `src/platform/storage/` (presign + request accessor); Config: four R2 keys +
  redaction; Deployment: vars for account/bucket + secrets documented in the README; Budget:
  dependency-confinement rule and the bundle delta (measured by `budget:check`).

## Acceptance Criteria

1. `createObjectPresigner` builds path-style URLs on the R2 S3 endpoint with
   `X-Amz-Algorithm`, `X-Amz-Credential` (scope `auto/s3/aws4_request`), `X-Amz-Date`,
   `X-Amz-Expires`, `X-Amz-SignedHeaders=host`, and a 64-hex `X-Amz-Signature`; identical
   inputs + clock produce identical URLs; a different clock changes the signature.
2. Keys encode segment-wise (`photos/cat image.png` → `photos/cat%20image.png`); expiry bounds
   and key validation raise `VALIDATION_FAILED`; incomplete configuration fails fast.
3. The pinned signer reproduces AWS's documented SigV4 vector (committed as a test), and the
   wrapper's output for fixed inputs is frozen as a golden URL.
4. `presignerFrom(context)` returns the port when configured and raises `INTERNAL` when not;
   the secret is redacted from logs (spec).
5. `budget:check` confines `aws4fetch` to the platform module with fixtures; `verify:ci` green.

## Decision Log

- 2026-10-11: delegate signing to `aws4fetch` instead of hand-rolling SigV4. -> canonicalization bugs are subtle and security-relevant; the dependency is tiny, Cloudflare-recommended for exactly this, and its output is pinned to AWS's documented vector in our suite
- 2026-10-11: path-style URLs (`<account>.r2.cloudflarestorage.com/<bucket>/<key>`). -> matches the AWS CLI/boto3 examples in R2's docs and keeps the canonical URI deterministic
- 2026-10-11: no content-type restriction in v1. -> signing an upload's content-type is a consumer-driven refinement; the profile-image task can add it when it needs it (simplicity first)
- 2026-10-11: module lands ahead of its first consumer, per the roadmap. -> the alternate reading (defer until needed) would leave the Phase 4 R2 item unchecked with a known consumer already in the parity backlog; the port is small and fully tested

## Completion Notes

The R2 port is in place: path-style SigV4 presigned GET/PUT URLs on
`<account>.r2.cloudflarestorage.com`, 300s default expiries with the 604800s platform cap,
segment-validated keys, `VALIDATION_FAILED` for caller mistakes, `INTERNAL` from the accessor
when the credentials are absent, and the secret joined to `SENSITIVE_KEYS`. Two implementation
details belong in the record: aws4fetch has **no** `expires` option (the expiry must be
pre-set as `X-Amz-Expires` in the URL before signing — an earlier probe passing `expires`
silently got the 86400 default), and the wrapper's assembly is frozen by golden URLs while the
dependency is pinned to AWS's documented vector in the suite. A credentialed R2 smoke (real
bucket, real upload) stays an explicit follow-up, the same lane pattern as the
deployment/dashboard-CPU evidence; the first consumer is the users profile-image flow already
sitting in the parity backlog.

Environment note for future sessions in this workspace: `NODE_ENV=production` makes npm prune
devDependencies on install, which removed the vitest plugin until `npm install --include=dev`
restored it; nothing in the repo depends on that, but installs here need the flag.
