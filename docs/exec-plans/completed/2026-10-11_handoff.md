# Handoff: dry-run and expiring per-action approvals (task 5.5)

- Status: completed
- Owner: fikrilal
- Risk: high
- Date: 2026-10-11
- Related ADRs / proposals: ADR-0009 (cfkit CLI and the verify gate); roadmap task 5.5

## Objective

The handoff closes the loop under explicit, expiring, per-action approvals:
`cfkit handoff dry-run --action commit|push|draft-pr` prints what would happen and issues a
one-time challenge; the mutation refuses without the matching approval and never offers merge
or deploy.

## Behavior reference

backend-core-kit: approvals as `0600` files under the task directory, `15 min` lifetime, only
the challenge hash persisted (sha256), bound to task fingerprint/authority/attempt/branch/remote/
changed paths (stale or mismatched → coded refusal), one file per action, mutation requires the
approval via env var, commit stages exactly the preflight task paths and asserts staged ==
taskPaths, push is non-force to the same branch, draft-PR uses `gh pr create --draft ...
--no-maintainer-edit`, and failure marks the approval `uncertain` ("inspect local and remote
state before any retry") with no auto-retry. Merge/deploy/migrate/force-push/PR-ready are absent.

## Design

- `cfkit handoff dry-run --task <id> --action <a>`: requires a verified task (5.4) whose lane
  passed; computes changed paths (git), writes `.cfkit/tasks/<id>/handoff/<action>.json`
  (0600) with `{action, status: "prepared", expiresAt, taskFingerprint, changedPaths,
challengeHash}`; prints the plan (paths, branch, remote) and the challenge **once**.
- Mutation `cfkit handoff <action> --task <id> --challenge <c>`: verifies the approval (exists,
  prepared, not expired, hash match, binding match), then: `commit` stages exactly the recorded
  paths and commits with the provided message heredoc-style; `push` pushes the current branch
  to the configured remote (no force); `draft-pr` writes the body file and runs `gh pr create
--draft` when `gh` exists, else prints the exact command and refuses (no silent fallback).
- Hard refusals: merge, deploy, migrate, force-push, branch deletion, PR-ready — absent from
  the CLI surface, asserted by tests. Operations outside the recorded paths, and any staged
  changes outside them, refuse. Failure marks the approval `uncertain` and instructs manual
  inspection; no retry.
- This is the tooling for the human-approved publication step; nothing here runs in CI.

## Acceptance Criteria

1. Dry-run issues a challenge bound to task/paths/attempt; the mutation refuses without it,
   after expiry (injected clock), on hash mismatch, and on stale bindings — each with its own
   coded message; tests use an injected clock.
2. `commit` stages exactly the recorded paths (extra staged changes refuse); `push` is
   non-force; `draft-pr` refuses cleanly when `gh` is unavailable.
3. Merge/deploy/migrate/force-push/PR-ready do not exist on the CLI surface (surface test).
4. A live dry-run → commit → push (to a scratch remote) cycle recorded as evidence.

## Completion Notes

The handoff closes the publication loop under explicit, expiring, per-action approvals: the
dry-run prints everything that would happen plus a one-time challenge (only its SHA-256 is
persisted, owner-only `0600`), and each mutation re-verifies the challenge, the expiry, the
revision, the changed paths, and the action before touching anything. Commit stages exactly the
approved paths and refuses pre-staged work outside them; push is non-force to the same branch;
draft-pr degrades to printing the exact `gh` command when `gh` is unavailable; merge, deploy,
migrate, and force-push do not exist on the CLI surface, which the tests pin.

The live scratch-repo cycle caught three real bugs the unit fixtures had not:

1. `changedPaths` trimmed porcelain lines before slicing the status prefix, producing paths
   shifted by one character (`ile.txt`) — the paths recorded in approvals and fingerprints were
   wrong and the classification was accidentally right only through prefix matching;
2. untracked directories appeared as entries (`.cfkit/`) and staged their contents, breaking
   the exact-staging assertion — the listing now uses `-uall` and filters `.cfkit/`;
3. a failed staging assertion threw out of the mutation handler and crashed the CLI instead of
   refusing cleanly — mutations are now wrapped, refusal printed, approval marked uncertain.

Residual semantics worth knowing: a wedged staging state (foreign work already staged) refuses
until the operator unstages — deliberate, matching the reference harness; the draft-PR action is
exercised only through its refusal path because `gh` authentication cannot be part of a
hermetic test.
