# CI lanes and governance (harness parity E17)

- Status: completed
- Owner: fikrilal
- Risk: medium
- Date: 2026-10-12
- Related ADRs / proposals: `_WIP/2026-10-12_harness-parity-proposal.md` §5.4 (rows 4.1-4.10), §7 batch E

## Objective

Turn the single CI job into lanes where the classifier is load-bearing, add the pull-request governance surface,
and make the workflow itself a contract that fixtures check.

## Behaviour reference (backend-core-kit)

Rows 4.1-4.10: a `risk` job running `ci classify`, a `full` job, a `runtime` job conditional on
`runtime_required`, a `governance` job (dependency review, secret scanning), a `required` aggregate tolerating
`skipped`, workflow invariants (job names, conditions, pins), a pull-request template, dependabot, commitlint as
a local hook, and the contract-change expectation in the CI standard.

## Design

- `.github/workflows/ci.yml`: five lanes. `risk` checks out with `fetch-depth: 0` (the classifier needs the
  range), resolves a base revision — `github.event.pull_request.base.sha`, else `github.event.before`, else
  `HEAD^` when the base is all zeros — and appends `ci classify` output to `$GITHUB_OUTPUT`. `full` runs
  `verify --profile full` and uploads coverage; `runtime` runs the `runtime` and `smoke` profiles only when
  `runtime_required == 'true'`; `governance` runs on pull requests (dependency review at `fail-on-severity: high`,
  a history/diff secret scan, the tracked-file scan and the production audit); `required` aggregates the four and
  tolerates `skipped` for the conditional lanes only.
- Every action is pinned by commit with its tag in the comment (dependency-review v5.0.0 and gitleaks v3.0.0
  SHAs resolved from the tags, not recalled), and every checkout sets `persist-credentials: false`.
- `scripts/ci/workflow.test.mjs` now **parses** the YAML and asserts: the exact job set, the `needs`/`if` wiring,
  the aggregate's `success|skipped` tolerance, the classifier's base-resolution lines and `$GITHUB_OUTPUT`
  append, the full/runtime split (the full lane must not run the runtime profiles), that no `run:` inlines a
  profile internal (`eslint`, `vitest`, `prettier`, `tsc`, `jscpd`, `spectral`, `wrangler`), the pins, the
  least-privilege permissions, the four checkouts persisting nothing, dependabot's two ecosystems, and the
  template's required sections and impact areas.
- `.github/pull_request_template.md`: risk class + lane, the eight impact areas from the plan schema,
  contract/parity impact, a runtime-evidence pointer, and "checks not run, and why".
- `.github/dependabot.yml`: weekly grouped npm updates and weekly action-pin updates.
- commitlint as a **local** hook: `commitlint.config.mjs` with the repository's 16-scope enum, `.githooks/commit-msg`,
  `npm run setup:hooks`, and `docs/guide/commit-conventions.md`. CI deliberately does not run it.
- `docs/standards/ci-cd.md` gains the lane table, the `required` status name, the pinning rule, the
  contract-change/changelog expectation, and two honest gaps (the gitleaks licence condition and the
  deliberately unrun `@scarf/scarf` postinstall).

## Constraints

- The classifier must be load-bearing: the `full` lane cannot silently keep running the runtime and smoke
  profiles, or the split would be decorative — a fixture asserts the absence.
- The lanes call profiles, never the steps inside them; the fixture fails on an inlined `eslint`/`vitest`/`tsc`.
- `required` is the only name branch protection needs, and it must not pass a failed or cancelled lane.
- Nothing in the pipeline writes to the repository: `permissions: contents: read` and
  `persist-credentials: false` on every checkout.
- Commit messages are a local convention, not a pipeline gate: the hook can be bypassed and CI stays out of it.

## Acceptance Criteria

1. Five lanes exist with the exact wiring asserted by the parsed-YAML fixture (fixtures).
2. The aggregate tolerates `skipped` for conditional lanes and nothing else (fixture).
3. No lane inlines profile internals; the full lane does not run the runtime profiles (fixtures).
4. Every action is commit-pinned with its tag comment, credentials are not persisted, permissions are
   `contents: read` (fixtures).
5. Governance carries dependency review, the secret scan, the tracked-file scan and the production audit
   (fixture); dependabot covers npm and actions weekly (fixture); the template asks for the risk class, the eight
   impact areas, contract impact, runtime evidence and skipped checks (fixture).
6. commitlint accepts a well-formed message and refuses a bad scope (probe), and CI does not run it (the
   workflow has no commitlint step).
7. `npm run verify`, `npm run verify:gates` and `npm run verify:ci` are green, and `ci.lanes`, `ci.governance`,
   `workflow.commit-conventions` plus `workflow.pr-template` flip to `present` (40 of 46).

## Decision Log

- 2026-10-12: the `full` lane runs `verify --profile full`, not `verify:ci`. -> the local `ci` profile stays the
  one-command entry point, but inside the pipeline the runtime lane must be real; a fixture pins the absence of
  the runtime profiles from the full lane.
- 2026-10-12: the invariants parse the YAML instead of scanning text. -> the repository already depends on
  `yaml`; parsing catches a restructured job that a regex would happily accept, and `if:` conditions become
  comparable strings rather than substrings.
- 2026-10-12: `fetch-depth: 0` on the `risk` checkout, with a `HEAD^` fallback for a zero base. -> the
  classifier reads a commit range, so a shallow checkout would make every push misclassify; the fallback is what
  a force-push to a new branch needs.
- 2026-10-12: the tag-comment assertion regex was widened to `v[\w.-]+`. -> the pins here are `v5.0.0`/`v3.0.0`;
  the old `v\d+` rule would have forced a comment that misnames the tag.
- 2026-10-12: commitlint stays local, and CI is asserted not to run it. -> a pipeline that fails on a subject
  line trains people to bypass the pipeline; the convention is enforced where the commit is written.
- 2026-10-12: dependency review and gitleaks are pinned from the tags I actually resolved. -> `v4` of
  dependency-review is not a tag (the latest is `v5.0.0`); a remembered SHA would have been a guess.
- 2026-10-12: two gaps are documented instead of implied. -> gitleaks-action needs a licence for organisations,
  and `@scarf/scarf` (a transitive dependency of commitlint) has a postinstall the install-script gate does not
  allow, so no telemetry runs; both are written down in the standard.

## Completion Notes

Batch E landed the lanes: `risk` publishes what the classifier decided, `full`, `runtime` and `governance` are
its consumers, and `required` is the single status name branch protection needs. The split is enforced rather
than described — the invariant suite parses the workflow and fails if the full lane starts running the runtime
profiles again, if a lane inlines a profile step, or if a pin or permission regresses. The governance lane
covers dependencies, the diff and the tracked tree; the two honest gaps (a gitleaks licence for organisations and
an unrun telemetry postinstall) are documented in the standard instead of being quietly assumed. Commit
conventions ship as a local hook with a fixture-visible refusal set, and CI stays out of it by design.
