# Config Platform (task 1.1)

- Status: completed
- Owner: fikrilal
- Risk: medium

- Related ADRs / proposals: ADR-0008 (env confinement), ADR-0005 (budget), ADR-0011 (strict baseline); roadmap task 1.1

## Objective

A typed, zod-validated configuration module (`src/platform/config`) that is the only place raw `env` is read. Invalid configuration fails fast with a readable message; valid configuration is parsed once per isolate. The Worker's `Env` type comes from `wrangler types` (generated, committed) instead of hand-maintained globals.

## Constraints

- Architecture: platform module; features never touch `env` (ADR-0008).
- Simplicity: only variables Phase 1 actually consumes (`APP_ENV`, `LOG_LEVEL`); no speculative config.
- Budget: parse-once per isolate; config keys count against the 64-vars/worker limit (ADR-0005).
- Strict lint budgets and the no-comments rule apply (ADR-0011).

## Impact Areas

- API / contract: no
- DB / migrations: no
- Auth / session: no
- Queue / jobs: no
- Config / secrets: yes
- Observability: yes (`LOG_LEVEL` consumed by task 1.8)
- Budget / free-tier footprint: yes (parse-once; var count)
- CI / release: no

## Acceptance Criteria

1. `parseConfig` validates and applies defaults; invalid values and the prod-debug invariant throw with a message naming the offending key.
2. `getConfig(env)` parses once per env object (memoized) and returns the same frozen instance.
3. `wrangler types` generates `worker-configuration.d.ts` (committed); `Env` fields come from `wrangler.jsonc` vars; `@cloudflare/workers-types` is removed.
4. `src/worker.ts` consumes config only through the module and stays `ExportedHandler<Env>`-typed.
5. `npm run verify` green; roadmap 1.1 checked; this plan moved to `completed/` with evidence.
