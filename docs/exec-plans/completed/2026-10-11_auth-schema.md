# Auth schema and migrations (task 3.1)

- Status: completed
- Owner: fikrilal
- Risk: high
- Date: 2026-10-11
- Related ADRs / proposals: ADR-0004 (D1 + Drizzle), ADR-0002 (data layer is independent; shapes are contract-owned), ADR-0006; roadmap task 3.1

## Objective

The auth tables land in Drizzle and as a reviewed, generated migration: `users`, `oidc_identities`, `sessions`, `refresh_tokens` (`idempotency_records` already exists from migration 0000). Columns cover the family behaviors and the contract's observable shapes: `MeDto` (email/verification/roles/status/profile fields), `MeSessionDto` (device info, ip, userAgent, lastSeenAt, expiresAt, revokedAt, status), and the rotation/reuse machinery (`refresh_tokens.token_hash` unique, `replaced_by_id` unique).

## Contract and behavior reference (from backend-core-kit)

- User: email unique; `emailVerifiedAt`; role `USER|ADMIN`; status `ACTIVE|SUSPENDED|DELETED` (+ suspendedAt/Reason); deletion request fields (3.6 scope); profile fields (displayName/givenName/familyName/profileImageFileId) — stored as `users` columns here (data layer is independent; backend uses a separate profile table).
- ExternalIdentity: provider `GOOGLE`, `subject`; unique `(provider, subject)` and `(userId, provider)`; email snapshot (never used for auth decisions).
- Session: `deviceId`, `deviceName`, `ip`, `userAgent`, `activeKey` unique nullable (`userId:deviceId`; revoked sessions clear it), `lastSeenAt`, `expiresAt` (fixed at creation; rotation never extends), `revokedAt`.
- RefreshToken: `tokenHash` unique (SHA-256 base64url of the opaque token), `expiresAt`, `revokedAt`, `replacedById` unique self-reference (rotation lineage; reused = revokedAt or replacedById set).

## Constraints

- Drizzle-first: tables in `src/platform/db/schema.ts`; migration generated by `drizzle-kit generate` (never hand-edited); `meta/` committed; local apply via `db:migrate:local`; the migrations drift gate must stay green.
- No password tables, no dead columns; timestamps as `integer({ mode: "timestamp_ms" })` for the new tables (typed Date mapping; the port-style `idempotency_records` stays as is).
- Statuses/roles/providers are typed unions via `$type<...>()` from shared literal unions; no DB enums in SQLite.
- Foreign keys with `onDelete: "cascade"` from sessions/refresh tokens/identities to users (and token → session); indexes only where a proven access path exists (user_id, session_id, revoked_at, active_key unique).
- Gate honesty: a Workers-pool spec exercises the real constraints (duplicate email rejected, duplicate `(provider, subject)` rejected, duplicate `token_hash` rejected, cascade delete removes sessions/tokens/identities) — constraints proven, not assumed.

## Impact Areas

- API / contract: no (no routes yet); DB / migrations: yes; Auth / session: enables 3.2–3.7; Budget: one migration, no behavior.
