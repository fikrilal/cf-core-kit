# Scaffold: feature and endpoint (task 5.1)

- Status: completed
- Owner: fikrilal
- Risk: medium
- Date: 2026-10-11
- Related ADRs / proposals: ADR-0009 (cfkit CLI and the verify gate); roadmap task 5.1

## Objective

`cfkit scaffold feature <name>` and `cfkit scaffold endpoint <operationId>` land; their output
passes `npm run verify` untouched. Feature scaffolds are contract-free slices; endpoint
scaffolds implement **pending pinned operations** (the contract already declares them, the
snapshot supplies everything) and move them to `implemented` in the parity manifest.

## Behavior reference

backend-core-kit's generator writes a tiered feature slice and _wires nothing_ (its README
next-steps ask the operator to add the module), with `it.todo` spec stubs so lint/tsc/tests
stay green; its removal tool is the inverse, and its CI smoke runs
scaffold → wire → lint/typecheck → remove → lint/typecheck. Our endpoint scaffold can do better
because the operation is pre-declared: path, method, params, security, `x-error-codes`, and the
204 response all come from the pin, so the generated route is contract-exact by construction.

## Design

- Pure generators (no I/O) return `{ files, edits, manifestMove }`; a thin writer applies them,
  refusing to overwrite existing files. Tests drive the pure parts against in-memory trees and
  a minimal fixture repo.
- `scaffold feature <kebab>`: validates the name (kebab, starts with a letter), creates
  `src/features/<name>/` with a typed service module (one real, tested function), its spec, and
  an `index.ts` barrel. No wiring, no contract surface — a capability slice that verifies
  untouched.
- `scaffold endpoint <operationId>`: requires the op to be pending in `coverage.json`; supports
  204-only operations with no request body and at most an optional `Idempotency-Key` header
  (the shapes most pending ops have); refuses DTO-bearing or body-shaped ops with an actionable
  message ("declare the DTOs in shared/contract first"). Requires the feature directory derived
  from the operationId prefix (camelCase → kebab) to exist. Generates
  `<feature>/<op-slug>.routes.ts` + a spec asserting the 204 + dialect, and edits exactly three
  files with stable anchors: `src/app.ts` (import + `register` call), `tools/contract/emit.entry.ts`
  (import + call, so the operation is emitted), and `tools/parity/coverage.json` (pending →
  implemented). Generated handlers carry `// TODO:` markers where real semantics belong.
- Verification: unit tests for validation/refusals/edits; the proof that output verifies
  untouched is a live scaffold → `verify:ci` → revert cycle recorded in the plan (the automated
  CI smoke lands in 5.6).

## Acceptance Criteria

1. Name validation and refusal messages are tested (bad names, existing feature, unknown or
   already-implemented operation, unsupported op shape, missing feature dir).
2. A scaffolded endpoint's three edits are anchor-checked (missing anchor → refuse before
   writing anything) and the manifest move is exact.
3. The generated route emits byte-compatible operation metadata for a real pending 204 op; a
   live scaffold cycle leaves `verify:ci` green (recorded evidence) and is fully reverted.
4. `cfkit scaffold` is wired into the CLI with usage text; `verify:ci` green.

## Completion Notes

Both commands are live and the "verifies untouched" claim is proven on the real repository, not
just in fixtures. Endpoint scaffolding implements a **pending pinned operation** end to end:
the route/operation metadata, error codes, security, and description all come from the
snapshot, the manifest move keeps its provenance block, and the scaffold runs `contract:emit`
so the committed OpenAPI artifact matches by construction. Feature scaffolding produces a
capability slice and wires the new cross-feature lint zones.

The live cycles were also the test for the tooling itself — they caught four real bugs the unit
fixtures had not:

1. the emitter import anchor matched the _closing line_ of a multiline import and spliced the
   new import inside it (fixed to insert after the complete statement, pinned by a placement
   assertion in the temp-workspace test);
2. the manifest reader dropped the `source` provenance block, breaking the pin check (fixed to
   preserve unknown keys, pinned by an assertion);
3. the scaffold did not regenerate `docs/openapi/openapi.yaml`, so the emit gate failed (the
   CLI now runs `scripts/contract/emit.mjs` after endpoint scaffolds);
4. the unit tests read the live manifest, so a scaffolded tree broke them (fixtures now derive
   a pending-state copy, proven by the suite passing while a live scaffold was present).

A fifth discovery shaped the design: the cross-feature boundary zones are enumerated per pair,
so a new feature would escape the rules the every-pair meta-test demands — the feature scaffold
therefore edits `eslint.config.mjs` (two zone entries per existing feature, anchored after
`zones: [`), and the live feature cycle confirmed the fast profile passes with it.
