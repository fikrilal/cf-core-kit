# Database (normative)

Status: normative (landed 2026-10-11). D1 with Drizzle is the data plane (ADR-0004); these are
the rules the platform code and features must follow.

## Schema and migrations

- The schema root is `src/platform/db/schema.ts`; features never define tables outside it.
- Migrations are generated by drizzle-kit into `db/migrations`, committed, and drift-checked
  byte-for-byte (the drift check regenerates into a temp path and compares). Generated SQL is
  never hand-edited — change the schema and regenerate.
- Constraints are tested against real D1 (`schema.spec.ts`), not assumed: cascades, partial
  unique indexes, and null semantics are asserted.

## Writes

- Budget: **≤ 2–3 rows written per API write request**, index amplification included (ADR-0004,
  free-tier-budget standard). Indexes exist only for proven read patterns; every index adds a
  row to every write touching its column.
- Multi-statement atomicity uses a single statement or one `db.batch()` — D1 has no interactive
  transactions across awaits. Conditional writes report their outcome through `meta.changes` or
  `RETURNING`, and callers branch on that, never on a re-read race.
- Time is injected: timestamps are `timestamp_ms` epoch milliseconds, written from the injected
  `Clock`; `Date.now()` does not appear in service/domain code.

## Reads and retention

- Lookups filter on indexed columns; unbounded scans are forbidden. Lists use the bounded
  `limit + 1` pagination pattern through the shared list-query pipeline.
- Sweeps are bounded (`SWEEP_BATCH_SIZE` rows per run through an ordered subquery), naturally
  idempotent, and housekeeping-only: correctness never depends on a sweep having run
  (queues-jobs standard).
- Retention semantics are explicit per table: sessions expire at `expires_at` with refresh
  tokens cascading; idempotency records carry their TTL in `expires_at` (ms epoch) and are
  ignored after expiry at use time.

## Verification

- Migrations: drift check (regen + byte compare) and `wrangler d1 migrations apply` in the
  deploy runbook.
- Behavior: pool specs against real D1 (cascades, partial uniques, bounded sweeps, rotation
  batches) plus the integration tier where features compose.
